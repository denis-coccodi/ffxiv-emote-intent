# Working in this repo

- This repo is **Emote Intent**, a Dalamud plugin for Final Fantasy XIV: the player types what they mean (`/feel so happy to see you`) and the plugin plays the best matching emote they have unlocked. It is distributed through our own custom plugin repository, not Dalamud's official list (its AI policy rejects plugins written entirely by AI).
- Every change goes through a branch named `bugfix/<description>` for a bug fix (`hotfix/` when a released version is broken) or `feature/<description>` for anything else, with Conventional Commits messages (`fix(matcher): …`, checked by the commit-msg hook in `.githooks`, which the first `dotnet build` sets up) and a pull request to `main`. `main` rejects direct pushes and requires the `test` check; merge only once it has passed and the user has said to merge. Follow the `feature-branch` skill before the first edit.
- `dotnet build -c Release` then `dotnet test -c Release --no-build` then `dotnet format --verify-no-changes` must all pass before pushing; the `test` check and the `pre-push` git hook run the same three.
- Follow the `csharp-best-practices` skill when writing or changing C# (analyzers and banned APIs as build errors, Core vs plugin, tests, 300-line files) and the `dalamud-plugin` skill for anything that touches Dalamud or the game. In Claude Code, hooks in `.claude/hooks/` format each C# file written and refuse edits to generated files.
- Layout: `EmoteIntent.Core` holds everything that doesn't need the game (the emote model, matching, the phrase bank) and is what the tests cover; `EmoteIntent` is the Dalamud plugin (commands, windows, reading the game data, playing the emote) and stays thin.
- Dalamud rules (dalamud.dev/plugin-publishing/restrictions): one command plays at most one emote, never loops or repeats emotes on its own, and nothing reaches the game server that the player couldn't do by typing. Verify Dalamud, Lumina and FFXIVClientStructs APIs against the installed versions (the XML docs in `%AppData%\XIVLauncher\addon\Hooks\dev`) rather than memory.
- Matching runs on the player's PC. AI is only a fallback the player switches on with their own API key or local model; the plugin never ships or calls a key of ours. Remembering a phrase → emote only happens when the player ticks it, and can always be undone.
- Several Claude windows and agents may work on this repo at once, so make each change in its own git worktree, stage files by name and don't use `git stash` (the `everise` plugin's guard, switched on in `.claude/settings.json`, blocks the commands that would trample others' work).
- Keep `README.md` in step with what the plugin does, in the same pull request, and document only what exists.
